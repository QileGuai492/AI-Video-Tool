## 1. 功能需求列表（Product Backlog）

按 MoSCoW 法则排序。每个需求项有稳定 ID，便于追踪到 Sprint 和用户故事。

### 1.1 Must Have（核心功能，Demo 必须实现）

| ID | 功能 | 说明 | 关联用户故事 |
| --- | --- | --- | --- |
| M1 | 用户系统 | 注册 / 登录（初期可简化，但需存储用户数据）、历史记录、角色库、模板库。 | US-6 |
| M2 | 提示词优化 | LLM 自动扩写用户输入，生成高质量提示词。 | US-1 |
| M3 | 首帧生成 | 调用文生图 API 生成高质量首帧，支持角色参考图。 | US-1, US-2 |
| M4 | 视频生成 | 调用至少 2 家视频生成 API（如 MiniMax 海螺、火山引擎即梦同源、可灵），支持文生视频、图生视频。 | US-1, US-2 |
| M5 | 角色一致性 | 基于上传的角色参考图，在单次生成任务中跨多个视频片段保持一致；支持用户选择是否跨对话保持角色一致。 | US-2 |
| M6 | 视频拼接 | 将多个 5-10 秒片段自动拼接为 1 分钟左右成片（含过渡效果）。 | US-3 |
| M7 | 音频生成 | TTS 生成台词 / 解说（多音色可选）；AI 根据视频内容推荐 / 匹配 BGM，或用户手动上传。 | US-1 |
| M8 | 后处理增强 | 视频超分（可选）、插帧（可选）、字幕添加（后期合成解决文字乱码）。 | US-4 |
| M9 | 调度 Agent | 核心大脑，基于 LangGraph 实现，负责编排上述流程，支持自主决策模型选择、是否重试、质量评估等。 | US-1 ~ US-6 |

### 1.2 Should Have（重要，后续迭代）

| --- | --- | --- |

| S3 | 成本估算显示 | 生成前估算、生成后记录。 |
| S4 | 本地 / 云端存储管理 | 统一管理生成文件。 |

| C4 | 移动端适配 | App / 小程序。 |

## 2. 用户故事（User Stories）

| 编号 | 用户故事 | 对应需求 | 对应 Sprint |
| --- | --- | --- | --- |
| US-1 | 作为创作者，我希望输入“一只猫在雨天奔跑”后，系统能自动优化提示词、生成首帧、生成视频、配上雨声音效和背景音乐，并输出可直接发布的视频。 | M2, M3, M4, M7, M9 | Sprint 1~4 |
| US-2 | 作为创作者，我希望上传我的角色照片后，后续所有生成的视频片段中该角色外貌一致，即使跨多个对话任务也能保持一致。 | M3, M4, M5 | Sprint 2 |
| US-3 | 作为创作者，我希望选择视频比例为 9:16，并生成 60 秒的短视频，系统自动拼接成片。 | M6, S1 | Sprint 2 |
| US-4 | 作为创作者，我希望能为视频添加自动生成的字幕，且文字清晰无乱码。 | M8 | Sprint 3 |
| US-5 | 作为创作者，我希望看到每次生成任务的花费估算，并能选择不同质量档位控制成本。 | S2, S3 | Sprint 4 |
| US-6 | 作为创作者，我希望能保存我的历史记录和常用模板，下次快速复用。 | M1 | Sprint 1 + 持续 |

## 4. 需求变更流程

1. 新增/变更需求时，先在本文件登记需求 ID 与优先级。
2. 评估影响的 Sprint、API、数据模型。
3. 同步更新 `03-迭代计划.md`、`06-接口设计.md`、`05-数据模型.md`。
4. 涉及架构决策时，在 `04-技术架构.md` 或 `docs/adr/` 记录。

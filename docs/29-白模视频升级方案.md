# 29 - 白模视频升级方案

> 状态：待评审  
> 最近更新：2026-08-21

## 1. 背景

“白模视频”（3D 灰盒预演 / Greybox / Blockout / Previs）是目前 AI 视频生成从“抽卡”走向“可控生产”的关键技术。

核心思路：

1. 用低精度 3D 模型（方块、球体、灰模人形）搭建场景、角色站位、动作路径、相机运镜。
2. 导出白模视频。
3. 将白模视频 + 角色参考图 + 场景参考图交给支持视频参考的 AI 视频模型。
4. AI 保留白模的运镜、动作、站位和时序，重建最终材质、光影、角色外观与环境。

参考来源：

- [Seedance 2.5 白模渲染：从灰盒预演到成片](https://pixo.video/zh/blog/seedance-previz-blockout)
- [Seedance 2.5 White-model storyboard](https://github.com/allenGKC/Seedance-2.5/blob/main/skill/seedance-25/references/white-model-storyboard.md)
- [Seedance 2.5 reference (ByteDance)](https://github.com/smixs/visual-skills/blob/main/video/references/seedance-25.md)

## 2. 已确认的方向

根据产品讨论，确定以下方向：

1. **白模模块形态**：内置 Web 端 3D 灰模编辑器 + Blender 高级导出；Blender 先做本地导出，后续再做容器化渲染服务。
2. **白模生成方式**：第一版先做**自由建模 + 关键帧动画**；预设模板库作为基础能力；**文字自动生成白模放后一期**。
3. **视频模型策略**：当前还没有 Seedance 2.5 API Key，先走 **SiliconFlow 降级方案**；同时保留 Provider 抽象，后续接入 Seedance 2.5。
4. **前端方向**：直接开始 React + Three.js 正式前端，并与白模后端接口同步开发。
5. **用户复杂度**：兼顾简单模式与高级模式。

## 2.1 当前已实现

- Three.js 白模编辑器：自由建模、关键帧、相机、录制、上传转 MP4。
- 白模项目/模板 API。
- 白模降级流水线：按镜头抽帧、逐镜头图生视频、拼接。
- 镜头切点与镜头动作/运镜描述编辑。
- 镜头描述合并进逐镜头生成提示词。
- Blender 本地导入 Add-on。
- 前端任务中心、模板市场、成本中心。

## 3. 视频模型调研结论

### 3.1 推荐首选：Seedance 2.5（即梦）

Seedance 2.5 是目前对“白模预演”支持最直接的生产级模型：

| 能力 | Seedance 2.5 |
| --- | --- |
| 白模视频参考 | ✅ 官方支持 3D 白模 blockout 控制 |
| 视频参考数量 | 10 个视频参考，单段 2~30s，总时长 ≤30s |
| 图片参考数量 | 30 张 |
| 音频参考数量 | 10 个 |
| 单次生成时长 | 最长 30s，可扩展 |
| 时间戳控制 | 支持秒级时间戳 |
| 多镜头 | 支持多镜头/多宫格分镜 |
| Blender/Maya 插件 | 官方生态支持，可直传即梦 |

结论：**白模升级首选接入 Seedance 2.5 API 或即梦开放平台。**

### 3.2 备选模型

| 模型 | 特点 | 适合场景 |
| --- | --- | --- |
| Agnes AI | 声称免费的全模态 API，支持图生视频/关键帧 | 低成本降级白模流程 |
| Kling / 可灵 | 国内可用，支持图生视频、运镜控制 | 单镜头图生视频 |
| PixVerse C1 | 面向影视制作，强调分镜/工业流程 | 影视级分镜 |
| Luma Scenes / Ray | Storyboard-first，支持场景控制 | 分镜到视频 |
| Runway / Veo / Sora | 世界模型方向，物理一致性更强 | 长期演进 |

### 3.3 世界模型（World Model）趋势

世界模型的目标是让模型理解并模拟物理世界，而不只是“生成看起来像视频的像素”。

代表方向：

- OpenAI Sora：把视频生成定义为“世界模拟器”。
- Google Genie / Veo：可交互世界模型 + 视频生成。
- 国内多家厂商也在向“世界模型”演进。

白模预演与世界模型是互补关系：

- 白模提供结构控制。
- 世界模型提供物理一致性和长期动作推理。
- 未来可以把“白模场景”直接作为世界模型的初始状态输入。

本项目应保持 Provider 抽象，为世界模型类接口预留扩展点。

### 3.4 降级方案（当前 SiliconFlow）

当前还没有 Seedance 2.5 API Key，因此先用 SiliconFlow 完成降级版白模流程。

#### 整体流程

```text
白模项目（Three.js 场景 + 关键帧动画）
  → 渲染白模视频（浏览器录制 / Blender 本地渲染）
  → 按镜头/节奏抽关键帧
  → 每镜头用“关键帧 + 角色/场景参考图”做图生视频
  → 多镜头片段拼接
  → 输出成片
```

#### 详细步骤

1. **创建白模项目**
   - 用户在 Three.js 编辑器中自由建模、设置关键帧动画、相机运镜。
   - 保存场景 JSON。

2. **渲染白模视频**
   - 第一版：Three.js 前端用 `MediaRecorder` 录制 WebM，或通过 Canvas 逐帧导出后合成 MP4。
   - 后续：本地 Blender Add-on 渲染更高质量 MP4。

3. **拆分镜头**
   - 用户在白模时间轴中标记镜头切分点。
   - 后端保存每个镜头的起止时间、相机、动作摘要。

4. **抽取关键帧**
   - 使用 FFmpeg 从白模视频中按镜头抽取关键帧：
     - 每镜头至少 1 帧（首帧）。
     - 镜头较长时每 0.5~1 秒补一帧，用于保持动作连续。
   - 关键帧只作为“结构参考”，最终外观由角色/场景参考图决定。

5. **生成镜头提示词**
   - 每个镜头生成独立提示词：
     - 声明白模对象 → 最终角色/道具/场景的映射。
     - 描述该镜头动作、运镜、景别、光线。
     - 声明“不保留白模材质、轨迹线、坐标线、相机锥体”。

6. **逐镜头图生视频**
   - 对每个镜头：
     - 输入：该镜头首帧关键帧 + 角色参考图 + 场景参考图。
     - 调用 SiliconFlow 图生视频接口。
     - 使用相同 seed（如果支持）和固定提示词模板，减少随机性。
   - 生成结果作为该镜头片段。

7. **镜头拼接**
   - 使用现有 `VideoStitcher` 拼接所有镜头片段。
   - 如果相邻镜头动作不连续，可在拼接时加入转场（叠化/匹配剪辑）。

8. **成片后处理**
   - 配音、字幕、质量检查等沿用现有流水线。

#### 连续性增强手段

| 问题 | 手段 |
| --- | --- |
| 角色外观漂移 | 每个镜头都传入同一组角色参考图 |
| 动作不连续 | 上一镜头尾帧作为下一镜头首帧/参考 |
| 运镜不连续 | 在提示词中固定相机高度、运动方向、景别 |
| 材质/光影漂移 | 在提示词中统一描述最终材质、光源方向 |
| 抽卡随机 | 尽量固定 seed，记录每次生成参数 |

#### 优缺点

优点：
- 不需要新模型 Key，当前 SiliconFlow 可直接跑通。
- 架构上与 Seedance 2.5 方案兼容，后续只需把“抽帧图生视频”替换为“白模视频直接参考”。

缺点：
- 运镜和动作连续性弱于视频参考方案。
- 镜头越多，拼接不一致风险越高。
- 需要更精细的提示词和关键帧策略。

## 7. 白模生成链路

### 7.1 预设模板库

内置模板（应用启动时按名称幂等写入）：

- 人物行走模板
- 产品展示模板
- 双人对话模板
- 场景空镜模板
- 追逐动作模板
- 多镜头分镜模板

用户选择模板后进入编辑器微调。

### 7.2 自动从文字生成白模（基础已实现）

流程：

```text
用户文案
  → LLM 生成镜头脚本（镜头数、时长、角色、动作、运镜）
  → 场景脚本（布局、物体、角色位置）
  → 生成 Three.js 场景 JSON
  → 前端渲染预览
  → 用户确认/微调
  → 渲染白模视频
```

当前已实现基础版：
- `POST /api/v1/previs/generate`：调用 LLM 生成场景 JSON 并创建 `auto` 模式项目。
- 前端“文字生成白模”按钮：输入文案后自动生成并加载到编辑器。
- 后续可继续增强镜头脚本质量和模板化生成。

### 7.3 自由建模 + 关键帧动画（第一版重点）

- 添加基础几何体：方块、圆柱、球体、平面、灰模人形。
- 支持对象选择、移动、旋转、缩放。
- 支持给对象添加关键帧：
  - 位置关键帧
  - 旋转关键帧
  - 缩放关键帧
- 支持相机：
  - 自由相机
  - 相机路径关键帧
  - 运镜预设（推、拉、摇、移、跟、环绕）
  - 视角预设（前/后/左/右/顶/透视）与一键重置
- 多镜头并发生成：后端通过 `VIDEO_SEGMENT_CONCURRENCY` 控制最大并发数。
- 支持时间轴：
  - 播放/暂停
  - 拖动时间
  - 镜头切分点
- 导出场景 JSON / 白模视频。
- 可导出到 Blender 精修。

预设模板库作为第一版的辅助能力，用户可以基于模板开始，也可以从空白场景自由搭建。

### 7.4 Blender 高级导出

- 提供 Blender Add-on 或独立脚本。
- 支持导入 Three.js 场景 JSON。
- 在 Blender 中精修动作、镜头、灯光。
- 渲染白模视频并回传平台。

## 8. 提示词模板

### 8.1 粗白模模板

```text
参考@视频1的运镜、动作路径、角色站位与镜头节奏。
将其中[蓝色人形]映射为@图片1的[女主]；将[橙色人形]映射为@图片2的[男主]。
[描述连续动作、表情、对话与光线变化。]
场景使用@图片3的[环境]。
全程保持角色身份、比例、站位和动作连续；不保留白模材质、轨迹线、坐标线或相机锥体。
```

### 8.2 细白模模板

```text
将@视频1的细颗粒白模渲染为最终成片。
几何结构、人物动画、机位和切镜时序不变。
[按时间点描述材质、灯光、环境、特效变化。]
去除全部坐标线、轨迹线、相机锥体、视口网格和调试文字。
```

### 8.3 多宫格分镜模板

```text
@图片1是按左到右、上到下排列的[N]格连续分镜，每格代表一个完整镜头。
角色A参考@图片2，角色B参考@图片3，场景参考@图片4。
镜头1（0–Xs）：[构图、景别、运镜、动作、落幅]。
镜头2（X–Ys）：[承接、运镜、动作、落幅]。
全片保持人物、服装、比例、道具、光线方向与空间连续。
```

## 9. 编排流水线

当前：

```text
PromptAgent → ImageAgent → VideoGenAgent → Audio/Subtitle → PostProcess
```

升级后：

```text
PromptAgent → PrevisAgent → ImageAgent → VideoGenAgent(参考白模) → Audio/Subtitle → PostProcess
```

新增 `PrevisAgent`：

1. 根据文案生成镜头脚本。
2. 选择/生成白模场景。
3. 调用渲染服务生成白模视频。
4. 生成“白模对象 → 最终角色/道具/场景”映射提示词。
5. 交给 VideoGenAgent。

## 11. 风险与应对

| 风险 | 应对 |
| --- | --- |
| Seedance 2.5 API 尚未开放/成本高 | Provider 抽象，先 SiliconFlow 降级 |
| 3D 编辑器开发量大 | 第一版聚焦自由建模 + 关键帧，不追求完整 DCC |
| 自由建模学习成本高 | 同时保留模板库和简单模式 |
| 文字→白模生成不稳定 | 放后一期，先稳定手动/模板链路 |
| Blender 服务部署复杂 | 先本地导出脚本，再容器化 |
| 白模到成片映射不稳定 | 沉淀提示词模板 + 评测用例持续回归 |

## 12. 验收标准

- 用户可以在 Three.js 编辑器中自由添加几何体、设置关键帧动画和相机运镜。
- 用户可以将白模场景保存到后端，并渲染/导出白模视频。
- 提交生成任务时可以选择白模视频，走 SiliconFlow 降级流程。
- 成片尽量保留白模的运镜、动作和空间关系。
- 高级用户可以将场景导出到 Blender 精修。
- 前端提供简单模式与高级模式。
- 文字自动生成白模作为后一期验收项。

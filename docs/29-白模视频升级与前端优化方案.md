## 1. 背景：什么是“白模视频”

“白模视频”又称 **3D 灰盒预演（Greybox / Blockout / Previs）**，是目前 AI 视频生成领域用来解决“抽卡”、运镜不可控、角色不一致、多镜头不连续的重要手段。

核心思路：

1. 先用低精度 3D 模型（方块、球体、圆柱、灰模人形）搭建场景、角色站位、动作路径、相机运镜和光线节奏。
2. 导出一段“白模视频”作为参考。
3. 将白模视频 + 角色参考图 + 场景参考图一起交给 AI 视频模型。
4. 让 AI **保留白模中的结构、运镜、动作和时序，重建最终材质、光影、角色外观和环境细节**。

- [Seedance 2.5 白模渲染：从灰盒预演到成片](https://pixo.video/zh/blog/seedance-previz-blockout)

## 2. 白模的两种粒度

| 类型 | 用途 | 输入 | 输出控制重点 |
| --- | --- | --- | --- |
| 粗白模（Coarse） | 控制运镜、走位、动作路径、站位、镜头节奏 | 简单几何体 + 灰模人形 | 动作骨架、路径、遮挡、镜头 |
| 细白模（Fine） | 控制材质、光影、风格、最终渲染 | 较完整的预演模型 | 几何、动画时序、机位、灯光变化 |

## 3. 升级方案

### 3.1 目标

让本项目支持“白模预演 → AI 成片”的工业化工作流，提升：

- 运镜可控性
- 角色一致性
- 动作连续性
- 多镜头衔接
- 用户创作效率

### 3.2 数据模型升级

建议为 `VideoTask` 增加字段：

```text
previs_video_url     # 白模/灰盒预演视频地址
previs_type          # none / coarse / fine
storyboard_url       # 多宫格分镜图地址
camera_script        # 镜头脚本 JSON
reference_video_url  # 给视频模型使用的参考视频
```

如后续做复杂项目，可新增：

```text
PrevisProject
├── id
├── user_id
├── title
├── blender_script / threejs_scene
├── previs_video_url
├── mapping_rules   # 白模对象 -> 最终角色/道具/场景的映射
└── created_at
```

### 3.3 Provider 扩展

当前 `VideoGenerationRequest` 只支持 `first_frame_url` 和 `reference_image_urls`。

需要扩展：

```text
reference_video_url: str | None
previs_type: str | None
```

并让 `VideoProvider` 支持视频参考输入。

- SiliconFlow 当前 Wan2.2 主要支持图生视频，是否支持“视频参考”需要确认。
- 如果支持：直接在 submit 时上传白模视频 URL。
- 如果不支持：降级方案：
  - 白模视频拆帧为关键帧；
  - 使用“图生视频 + 分镜提示词”逐镜头生成；
  - 最后用现有拼接服务合成。

### 3.4 编排流水线升级

当前流程：

```text
PromptAgent → ImageAgent → VideoGenAgent → Audio/Subtitle → PostProcess
```

升级后：

```text
PromptAgent → PrevisAgent → ImageAgent → VideoGenAgent(参考白模视频) → Audio/Subtitle → PostProcess
```

新增 `PrevisAgent` 职责：

1. 根据用户文案生成镜头脚本。
2. 调用 Blender / Godot / Three.js 服务生成白模视频。
3. 输出粗/细白模视频。
4. 生成“白模对象 → 最终角色/道具/场景”的映射提示词。

### 3.5 提示词模板

参考 Seedance 官方工作流，沉淀以下模板：

#### 粗白模模板

```text
参考@视频1的运镜、动作路径、角色站位与镜头节奏。
将其中[蓝色人形]映射为@图片1的[女主]；将[橙色人形]映射为@图片2的[男主]。
[描述连续动作、表情、对话与光线变化。]
场景使用@图片3的[环境]。
全程保持角色身份、比例、站位和动作连续；不保留白模材质、轨迹线、坐标线或相机锥体。
```

#### 细白模模板

```text
将@视频1的细颗粒白模渲染为最终成片。
几何结构、人物动画、机位和切镜时序不变。
[按时间点描述材质、灯光、环境、特效变化。]
去除全部坐标线、轨迹线、相机锥体、视口网格和调试文字。
```

### 3.6 任务状态机

新增状态：

```text
generating_previs → previs_ready → generating_video → ...
```

### 3.7 存储

- 白模视频存入 `uploads/previs/` 或 OSS `previs/` 目录。
- 镜头脚本以 JSON 存入数据库或 OSS。

## 4. 前端优化方案

### 4.1 当前 Streamlit 前端问题

- 单页表单，缺少实时任务进度刷新。
- 没有视频预览 / 参考视频对比。
- 没有白模预演工作区。
- 批量任务没有聚合进度面板。
- 模板市场没有可视化卡片。
- 错误信息展示不友好。

### 4.2 Streamlit 短期优化

1. **白模预演工作区**
   - 上传白模视频或调用后端生成。
   - 展示白模预览。
   - 编辑镜头脚本 / 角色映射。
   - 一键提交生成。

2. **任务进度实时刷新**
   - 使用 `st_autorefresh` 定时拉取任务状态。
   - 展示当前阶段、进度条、耗时。

3. **批量任务面板**
   - 展示批次内每个任务状态。
   - 聚合成功 / 失败 / 进行中数量。

4. **视频对比预览**
   - 并排展示：参考图 / 白模视频 / 成片。
   - 支持播放、暂停、下载。

5. **模板市场 UI**
   - 卡片式模板列表。
   - 支持“复制到我的模板”。

6. **成本展示**
   - 显示当前用户总成本、任务数、调用次数。

### 4.3 长期前端（React + Vite + Ant Design）

推荐架构：

```text
React + TypeScript + Vite
Ant Design 5
Zustand / Redux Toolkit
Three.js / react-three-fiber（3D 灰模画布）
Video.js / Plyr（视频播放）
```

页面规划：

| 页面 | 功能 |
| --- | --- |
| 工作台 | 提示词、参考图、角色、白模预演、分镜时间轴 |
| 任务中心 | 任务列表、进度、批量、取消/重试、下载 |
| 模板市场 | 分类、搜索、卡片、复制 |
| 成本中心 | 余额、明细、趋势图 |
| 设置 | API Key、默认模型、存储配置 |

核心组件：

- `PrevisCanvas`：Three.js 灰模画布，支持拖拽角色、设置相机路径。
- `TimelineEditor`：分镜时间轴，控制每镜头时长、运镜、动作。
- `VideoCompare`：多视频对比播放器。
- `TaskProgressBoard`：批量任务进度聚合。

### 4.4 前后端接口扩展

需要新增/调整 API：

```text
POST /api/v1/previs/generate       # 生成白模预演
GET  /api/v1/previs/{task_id}      # 获取白模预演结果
POST /api/v1/generate/video        # 扩展支持 reference_video_url
GET  /api/v1/tasks/batch/{batch_id} # 批量任务进度聚合
```

## 5. 实施路线

| 阶段 | 内容 | 优先级 |
| --- | --- | --- |
| Phase 1 | 数据模型 + Provider 视频参考扩展 + 白模提示词模板 | P0 |
| Phase 2 | Blender/Godot 预演生成服务（可先支持上传白模视频） | P1 |
| Phase 3 | Streamlit 白模工作区 + 任务进度优化 | P1 |
| Phase 4 | React 正式前端 + Three.js 白模画布 | P2 |

## 6. 风险与应对

| 风险 | 应对 |
| --- | --- |
| 当前视频模型不支持视频参考 | 降级为“白模拆帧 + 图生视频 + 分镜拼接” |
| 白模生成依赖 3D 工具，学习成本高 | 先提供预设灰模场景模板 |
| 生成成本增加 | 白模预演仅高级用户/高级质量模式启用 |
| 白模到成片映射不稳定 | 沉淀提示词模板，加入评测用例持续回归 |

## 7. 验收标准

- 用户能上传/生成白模视频并提交 AI 成片任务。
- 成片保留白模的运镜、动作和空间关系。
- 角色一致性在连续多镜头中不丢失。
- 前端能预览白模与成片，并实时查看任务进度。
- 批量任务有聚合进度面板。

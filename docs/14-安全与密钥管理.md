# 14 - 安全与密钥管理

> 状态：待评审  
> 最近更新：2026-01-01  
> 所属文档库：[README](../README.md)

## 1. 目的

定义项目在密钥管理、用户认证、文件上传、数据存储和发布流程中的安全要求。

## 2. 密钥管理

### 2.1 环境变量

- 所有 API Key、数据库密码、JWT Secret 必须放在环境变量中。
- 仓库只提交 `.env.example`，不提交 `.env`。
- `.env.example` 中的值必须是空占位符或假值。

示例：

```dotenv
# .env.example
DATABASE_URL=postgresql://user:password@localhost:5432/ai_video
REDIS_URL=redis://localhost:6379/0
JWT_SECRET=please_change_me
MINIMAX_API_KEY=
TONGYI_API_KEY=
CLAUDE_API_KEY=
OSS_ACCESS_KEY_ID=
OSS_ACCESS_KEY_SECRET=
OSS_BUCKET=
OSS_ENDPOINT=
```

### 2.2 禁止事项

- 不把 API Key 硬编码到代码中。
- 不把 `.env` 提交到 Git。
- 不把密钥发送到前端。
- 不在日志中打印完整密钥。
- 不在截图 / 文档中暴露真实密钥。

### 2.3 密钥轮换

- JWT Secret 定期更换。
- 云服务 Key 建议使用子账号 / 最小权限。
- 疑似泄露时立即吊销并更换。

## 3. 用户认证

- 密码使用 bcrypt / argon2 哈希，不使用 MD5 / SHA1。
- JWT 设置过期时间（建议 24 小时），并提供刷新机制。
- 所有需要登录的接口校验 JWT。
- 资源访问必须校验归属：用户只能访问自己的角色、任务、模板。

## 4. 文件上传安全

- 上传文件必须校验：
  - 文件类型白名单（图片：jpg/png/webp；音频：mp3/wav；视频：mp4）。
  - 文件大小上限（图片 ≤ 10MB，音频 ≤ 50MB，视频 ≤ 200MB）。
  - 文件内容魔数校验，不能只看扩展名。
- 上传文件名统一重命名为 UUID，避免路径穿越。
- 上传目录不直接对外暴露，通过签名 URL 访问。

## 5. OSS 安全

- Bucket 默认私有。
- 文件访问使用 STS 临时凭证或签名 URL。
- 签名 URL 设置有效期（建议 30 分钟 ~ 24 小时）。
- 不开放 ListBucket 公共权限。

## 6. 外部 API 调用安全

- 外部 API Key 只保存在服务端。
- 调用外部 API 时记录费用和错误，但脱敏后再写日志。
- 对第三方 API 返回内容不做未经验证的执行 / 拼接。

## 7. 日志与监控

- 日志中禁止记录：密码、Token、API Key、OSS Secret。
- 错误日志可记录 `task_id`、错误码、错误消息，但需脱敏。
- 安全相关事件（登录失败、越权访问、上传异常）单独记录。

## 8. Git 与发布安全

- 提交前检查是否误提交 `.env`、密钥文件、本地数据库文件。
- `.gitignore` 必须包含：

```gitignore
.env
.env.*
!.env.example
*.pem
*.key
__pycache__/
*.pyc
node_modules/
dist/
.DS_Store
```

- 推送 GitHub 前使用 `git status` 和 `git diff --cached` 检查。
- 如已误提交密钥，立即撤销并轮换密钥。

## 9. 合规

- 不生成、不存储侵权或违规内容。
- 用户上传素材仅用于生成任务，不对外公开。
- 后续多用户阶段需补充隐私政策与内容审核。

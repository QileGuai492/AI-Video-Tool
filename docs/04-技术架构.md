# 04 - 技术架构

> 状态：已评审  
> 最近更新：2026-01-01  
> 所属文档库：[README](../README.md)

## 1. 技术选型

| 层次 | 选型 | 说明 |
| --- | --- | --- |
| 后端 | Python + FastAPI | 前后端分离，提供 RESTful API。 |
| 异步任务 | Celery + Redis | 处理耗时任务（视频生成、拼接）。 |
| 数据库 | PostgreSQL + SQLite（本地开发） | 用户、历史记录、角色库、模板。 |
| 文件存储 | 本地 / 阿里云 OSS | 通过 `StorageProvider` 抽象切换，存储生成的视频、图片、音频。 |
| AI 编排 | LangGraph | 多 Agent 调度、状态管理、条件分支。 |
| 前端 | React + Three.js | 正式前端，支持白模编辑器与任务中心。 |
| 部署 | 阿里云 ECS + Docker | 已有空闲服务器。 |
| 本地后处理 | FFmpeg + MoviePy | 视频拼接、字幕叠加、转码。 |

## 2. 系统架构图

```text
[用户浏览器]
    ↓ HTTP
[Nginx 反向代理]
    ↓
[FastAPI 后端]  ←→ Redis（队列） ←→ Celery Worker
    ↓                              ↓
[PostgreSQL]                 [AI 服务调用层]
                              ├── LLM API（Claude / GPT-4o-mini）
                              ├── 文生图 API（通义万相 / Flux / SD）
                              ├── 视频生成 API（MiniMax / 火山 / 可灵）
                              ├── TTS API（MiniMax / 阿里云）
                              └── 后处理（FFmpeg / MoviePy / 云端 GPU 按需）

[本地磁盘 / 阿里云 OSS]（通过 StorageProvider 抽象存储所有生成文件）
```

## 3. 核心流程

```text
用户输入
   ↓
PromptAgent：优化提示词、生成结构化参数
   ↓
ImageAgent：生成首帧（可选角色参考图）
   ↓
VideoGenAgent：生成多个 5-10 秒片段
   ↓
AudioAgent：TTS 配音 + BGM 推荐
   ↓
SubtitleAgent：生成字幕文件
   ↓
PostProcessAgent：拼接、叠加字幕、转场、转码
   ↓
QualityCheckAgent：质量评估 / 重试 / 更换模型
   ↓
输出成片 + 成本记录
```

## 4. 核心模块与 Agent 划分

| Agent | 职责 | 关键 API / 工具 |
| --- | --- | --- |
| PromptAgent | 优化用户输入，生成结构化提示词、风格、时长、比例。 | Claude API |
| ImageAgent | 生成首帧，支持角色参考图融合。 | 文生图 API（通义万相 / Flux） |
| VideoGenAgent | 调用视频生成 API，支持文生视频 / 图生视频，处理多片段生成。 | MiniMax / 火山 / 可灵 |
| AudioAgent | 生成台词文本（LLM）、TTS 合成、BGM 推荐。 | Claude + TTS + 音乐推荐逻辑 |
| SubtitleAgent | 生成字幕并叠加到视频（解决乱码）。 | Whisper（可选）+ MoviePy |
| PostProcessAgent | 视频拼接、超分、插帧、转码。 | FFmpeg、MoviePy、Real-ESRGAN（可选） |
| QualityCheckAgent | 视觉质量评估、成本控制、重试决策。 | 视觉语言模型（GPT-4V / Qwen-VL） |
| 调度 Agent | 总控，根据用户需求动态编排上述 Agent。 | LangGraph StateGraph |

## 5. 核心扩展点

### 5.1 Provider 适配层

所有外部 AI 服务通过统一接口调用，当前已实现 Mock Provider，后续可新增 MiniMax、通义万相、可灵等真实 Provider。

### 5.2 StorageProvider 存储抽象

- 接口：`upload(content, suffix, folder)`、`get_url(key)`。
- 实现：本地磁盘、阿里云 OSS。
- 通过 `STORAGE_BACKEND` 配置切换。

### 5.3 TaskOrchestrator 任务编排抽象

- 接口：`run(task_id)`。
- 当前实现：`SimpleTaskOrchestrator` 顺序流水线。
- 后续实现：`LangGraphOrchestrator` 状态图编排。
- Celery 任务只依赖该抽象，替换编排器不影响 API 层。

## 6. 架构原则

1. **外部 API 适配层隔离**：每个云服务商封装为独立 provider，核心流程不直接依赖具体厂商。
2. **异步任务优先**：所有耗时生成过程放入 Celery 队列，HTTP 层只负责提交与查询。
3. **状态可追踪**：任务状态、片段状态、成本记录持久化，便于重试与审计。
4. **本地优先后处理**：能用 FFmpeg / MoviePy 免费完成的不依赖付费云服务。
5. **前后端分离**：后端 API 独立，前端使用 React + Three.js，可独立部署与替换。
6. **存储可切换**：所有文件读写通过 `StorageProvider` 抽象，本地与 OSS 可切换。
7. **编排可替换**：任务流水线通过 `TaskOrchestrator` 抽象，为 LangGraph 留好替换位置。

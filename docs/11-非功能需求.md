# 11 - 非功能需求

> 状态：待评审  
> 最近更新：2026-01-01  
> 所属文档库：[README](../README.md)

## 1. 目的

本文档定义系统在功能之外必须满足的质量属性，作为开发、测试和验收的约束条件。

## 2. 性能

| 编号 | 指标 | MVP 目标 | 生产目标 |
| --- | --- | --- | --- |
| NFR-P1 | 单段 5 秒视频端到端生成耗时 | ≤ 5 分钟（含排队） | ≤ 3 分钟 |
| NFR-P2 | 60 秒成片全流程耗时 | ≤ 30 分钟 | ≤ 20 分钟 |
| NFR-P3 | 任务状态查询接口响应时间 | ≤ 300ms | ≤ 200ms |
| NFR-P4 | 普通 API 接口响应时间 | ≤ 500ms | ≤ 300ms |
| NFR-P5 | 同时排队任务数 | ≥ 10 | ≥ 50 |
| NFR-P6 | 单任务视频片段并行生成数 | 1（串行） | 3~6（受 API 配额限制） |

## 3. 可用性与可靠性

| 编号 | 指标 | 目标 |
| --- | --- | --- |
| NFR-A1 | 端到端生成成功率（含自动重试） | ≥ 80% |
| NFR-A2 | 外部 API 失败自动重试次数 | 默认 3 次 |
| NFR-A3 | 任务失败后必须保留失败原因 | 100% |
| NFR-A4 | 服务重启后未完成任务可恢复 | 支持（任务状态持久化） |
| NFR-A5 | 单点外部 API 不可用时系统不崩溃 | 支持 provider 切换 / 降级 |

## 4. 安全

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| NFR-S1 | 密码不得明文存储 | 使用 bcrypt / argon2 哈希 |
| NFR-S2 | API Key 不得进入前端或提交到 Git | 统一放服务端环境变量 |
| NFR-S3 | 文件上传必须校验类型、大小、内容 | 防止恶意文件 |
| NFR-S4 | OSS 文件默认私有，使用临时签名 URL 访问 | 不开放永久公读 |
| NFR-S5 | 所有敏感操作必须鉴权 | JWT 校验 + 资源归属校验 |

## 5. 数据保留

| 编号 | 需求 | 说明 |
| --- | --- | --- |
| NFR-D1 | 历史任务记录 | 默认永久保留，用户可删除 |
| NFR-D2 | 生成文件 | 默认保留 30 天，可配置清理策略 |
| NFR-D3 | 日志 | 保留 30 天，可配置归档 |
| NFR-D4 | 用户删除账号时 | 级联删除或匿名化个人数据 |

## 6. 易用性

- 创作页默认提供推荐参数，用户无需理解底层模型。
- 任务进度必须可视化（阶段、百分比、当前步骤）。
- 成本估算在提交前展示，避免“意外扣费”。

## 7. 兼容性

- 浏览器：Chrome / Edge / Safari 最新两个大版本。
- 视频格式：输出统一 MP4（H.264 + AAC）。
- 比例：16:9、9:16、1:1；后续可扩展。

## 8. 可维护性

- 所有外部 API 通过 provider 适配层封装。
- 核心流程不得依赖具体厂商 SDK。
- 关键模块必须有单元测试覆盖。
- 日志使用结构化格式，携带 `task_id` 便于追踪。

## 9. 可观测性

- 记录任务成功率、平均耗时、API 错误率、成本趋势。
- 支持按 `task_id` 查询完整链路日志。
- 对连续失败、成本超限、API 配额不足提供告警。

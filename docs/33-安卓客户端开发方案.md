# 32 - 安卓客户端开发方案

> 状态：已确认技术方向，待启动  
> 最近更新：2026-08-23  
> 所属文档库：[README](../README.md)

## 1. 项目目标

开发一个 **原生 Kotlin + Jetpack Compose** 的安卓客户端，作为现有 AI 视频生成工具的移动端入口，覆盖完整创作流程：

> 登录/注册 → 角色库 → 模板市场 → 3D 白模编辑 → 上传参考图/视频 → 视频生成任务 → 任务中心 → 下载/分享 → 设置

- **最低支持版本**：Android 8.0（API 26）
- **分发方式**：企业内部分发（APK / 企业签名）

## 2. 技术选型

| 领域 | 选型 | 说明 |
| --- | --- | --- |
| 语言 | Kotlin | 官方推荐 |
| UI | Jetpack Compose + Material 3 | 现代声明式 UI |
| 架构 | MVVM + Repository + UseCase | 分层清晰，易测试 |
| 依赖注入 | Hilt | 官方推荐 |
| 网络 | Retrofit + OkHttp + kotlinx.serialization / Moshi | 对接现有 REST API |
| 异步 | Coroutines + Flow | 配合任务轮询 |
| 本地存储 | Room | 缓存用户、角色、任务、模板 |
| 数据偏好 | DataStore | 保存 token、设置 |
| 图片加载 | Coil | 加载网络图片 |
| 视频播放 | ExoPlayer（Media3） | 播放/预览视频 |
| 视频上传 | OkHttp 自定义进度上传 | 支持大文件、断点续传（可选） |
| 3D 渲染 | Filament 或 SceneView | 原生 3D 白模编辑器 |
| 权限 | 相机/相册/通知 | 上传素材、任务完成通知 |
| 打包 | Gradle + 企业签名 | 输出 APK/AAB |

> 3D 白模编辑器原生重写建议用 **Filament**（Google 开源，PBR 渲染好，移动端性能强），或 **SceneView**（封装 Filament 的 Kotlin 库）。Three.js 场景 JSON 需要做一次数据映射。

### 模块划分建议（Gradle 多模块）

- `app`：壳工程、导航、DI
- `core:network`：Retrofit、拦截器、API 定义
- `core:database`：Room、Entity、DAO
- `core:designsystem`：主题、通用组件
- `feature:auth`：登录/注册
- `feature:home`：首页/工作台入口
- `feature:characters`：角色库
- `feature:templates`：模板市场
- `feature:previs`：3D 白模编辑器 + 项目
- `feature:tasks`：任务中心
- `feature:settings`：设置
- `feature:upload`：图片/视频上传
- `feature:player`：视频预览/下载

## 4. 功能模块拆解

### 4.1 登录 / 注册

- 对接现有 `/api/v1/auth/login`、`/api/v1/auth/register`
- 支持 Token 本地保存（DataStore）
- 自动登录、退出登录
- 密码强度校验（8 位以上，含字母+数字）
- 邮箱格式校验
- 记住账号（可选）

### 4.2 首页 / 工作台

- 展示最近项目、最近任务、快捷入口
- 展示当前用户信息

### 4.3 角色库

- 列表、创建、删除
- **上传参考图**（相册/拍照）→ 调 `/api/v1/upload`
- 多角度参考图管理
- 图片预览

### 4.4 模板市场

- 模板列表（内置/我的）
- 模板复制、删除
- 模板详情友好展示（不显示原始 JSON）

### 4.5 3D 白模编辑器（原生重写）

这是全功能版里工作量最大的模块。

**数据来源**

- 后端 `scene_json` 结构：objects / keyframes / cameraKeyframes / shotMarkers / shotDescriptions / duration

**原生实现**

- 用 Filament/SceneView 渲染：
  - 人形灰模（简化胶囊体/方块组合）
  - 地面、方块、圆柱、球体、平面
  - 灯光、网格辅助线
- 交互：
  - 单指旋转相机
  - 双指缩放/平移
  - 点选对象、属性编辑（位置/旋转/缩放）
  - 时间轴播放/暂停
  - 关键帧添加/删除
  - 镜头关键帧记录
- 导出：
  - 生成与 Web 端兼容的 `scene_json`
  - 调用现有 `/api/v1/previs/projects` 保存
- 录制：
  - 原生 3D 画面录制（MediaCodec + EGL）生成 MP4
  - 上传到 `/api/v1/previs/projects/{id}/video`

> 建议第一版先实现“查看 + 简单编辑 + 播放动画 + 保存场景”，录制功能放到第二阶段。

### 4.6 上传素材

- 图片上传：`/api/v1/upload`，file_type=image
- 视频上传：`/api/v1/upload`，file_type=video
- 参考视频生成白模：`/api/v1/previs/generate-from-video`
- 高级动态白模：`/api/v1/previs/generate-from-video-advanced`
- 大文件进度条、失败重试

### 4.7 视频生成任务

- 提交生成：`/api/v1/generate/video`、`/api/v1/generate/batch`
- 支持传：
  - 文案 prompt
  - 首图 image_url
  - 多张参考图 reference_image_urls
  - 白模视频 previs_video_url
  - 角色 character_id
  - 时长、比例、质量
- 任务轮询：`/api/v1/generate/status/{task_id}`
  - 前台轮询 + WorkManager 后台轮询
  - 完成后推送通知
- 取消/重试：`/api/v1/generate/{id}/cancel|retry`
- 下载：`/api/v1/generate/{id}/download`

### 4.8 任务中心

- 列表、状态中文显示
- 取消、重试、下载、分享
- 进度展示

### 4.9 设置

- 用户信息（邮箱、密码）
- 默认比例/质量/模型
- 成本上限
- 清除缓存、退出登录

## 6. 本地数据与缓存

- **Token / 用户信息**：DataStore
- **角色、模板、任务、项目**：Room 缓存，进入页面先显示缓存再刷新
- **视频文件**：应用私有目录 + MediaStore（可选）
- **3D 场景**：本地保存最近编辑的 `scene_json`

## 7. 安全与合规

- Token 存 DataStore（加密可选，企业内部分发可用 EncryptedSharedPreferences 替代）
- HTTPS 必须开启（后端生产环境）
- 上传文件类型/大小校验
- 不在日志中打印密码/Token
- 企业分发需要准备签名证书

## 8. 测试策略

- **单元测试**：ViewModel、UseCase、Repository Mock
- **UI 测试**：Compose UI Test
- **网络测试**：MockWebServer
- **3D 编辑器测试**：核心场景解析/坐标转换单测
- **端到端**：连接测试环境跑通注册→上传→生成→下载

## 9. 里程碑计划（建议 8~10 周）

| 阶段 | 内容 | 工期 |
| --- | --- | --- |
| M1 项目搭建 | 多模块工程、网络层、登录、导航、主题 | 1 周 |
| M2 核心数据 | 角色库、模板市场、设置、上传 | 2 周 |
| M3 任务中心 | 提交任务、轮询、取消/重试、下载 | 2 周 |
| M4 3D 白模编辑器 | scene_json 解析、渲染、编辑、播放、保存 | 3 周 |
| M5 白模录制上传 | 原生录制、上传、参考视频生成白模 | 2 周 |
| M6 打磨发布 | 测试、性能、企业签名、打包 APK | 1 周 |

## 10. 风险与依赖

- **3D 白模编辑器原生重写工作量最大**：建议先做“查看/播放/简单编辑”，再扩展录制。
- **scene_json 兼容**：需要与 Web 端 Three.js 数据结构严格对齐，建议先做一个转换器并测试。
- **视频上传大文件**：需要 OkHttp 进度 + 超时配置，必要时做分片。
- **后台任务轮询**：Android 后台限制严格，建议 WorkManager + 通知。
- **后端生产地址/HTTPS**：需要提供正式服务器地址和证书。
- **cpolar 公网地址不稳定**：只适合开发调试，正式版必须用固定域名。

# 13 - 测试策略

> 状态：已实现（pytest + Vitest + Harness）  
> 最近更新：2026-08-23  
> 所属文档库：[README](../README.md)

## 1. 目的

定义项目的测试分层、覆盖范围和执行方式，保证核心链路可回归、外部 API 可模拟、上线前有基本质量保障。

## 2. 测试金字塔

```text
        ▲  端到端测试（少量）
       ▲▲  集成测试（适量）
      ▲▲▲  单元测试（大量）
```

| 层级 | 对象 | 数量策略 |
| --- | --- | --- |
| 单元测试 | 工具函数、状态机、成本计算、提示词模板 | 大量，尽量覆盖边界 |
| 集成测试 | FastAPI 路由、数据库、Celery 任务、Provider 适配层 | 覆盖核心链路 |
| 端到端测试 | 提交任务 → 轮询 → 下载成片（Mock 外部 API） | 1~2 条主链路即可 |

## 3. 单元测试

必须覆盖：

- 提示词优化模板与参数拼装。
- 视频比例 / 时长 / 分段数量计算。
- 成本估算与累计成本计算。
- 任务状态机转换。
- 错误码映射。
- 文件名校验与安全处理。

## 4. 集成测试

必须覆盖：

- 注册 / 登录 / JWT 鉴权。
- 角色上传与列表。
- 提交视频生成任务。
- 查询任务状态。
- 任务失败与重试。
- 任务 UID 跨用户隔离。
- 删除任务及关联数据。
- 多角色映射字段保存。
- 台词文本字段保存。
- 历史记录分页。
- 模板保存与读取。

## 5. 外部 API 测试策略

- 所有外部 API 调用必须通过 Provider 适配层。
- 测试环境使用 **Mock / Fake Provider**，不真实调用付费 API。
- 对每家真实 API 提供 **冒烟测试脚本**，仅在手动或 CI 指定环境执行。
- 记录每家 API 的错误码映射到内部错误码。

建议目录：

```text
tests/
├── unit/
├── integration/
├── e2e/
└── mocks/
    ├── providers/
    └── fixtures/
```

## 6. 端到端测试

- 使用 `docker-compose` 启动完整本地环境。
- 使用 Mock Provider 模拟外部 API。
- 主链路：登录 → 提交任务 → 轮询到完成 → 获取成片 URL。

## 7. 测试数据

- 提供固定种子数据：测试用户、角色、模板、历史任务。
- 外部 API 返回的响应保存为 fixture，保证测试可重复。
- 涉及金额的测试使用“分”为单位或 Decimal 精确比较。

## 8. 覆盖率目标

- 核心业务模块：行覆盖率 ≥ 80%。
- 整体项目：行覆盖率 ≥ 60%（MVP 阶段）。
- 新代码提交时不允许降低关键模块覆盖率。

## 9. CI 集成

每次提交 / PR 自动执行：

```text
linter（ruff / eslint 等）
→ 单元测试
→ 集成测试
→ 构建镜像
```

## 9.1 Harness 评测

项目内置 `eval_harness` 评测 Agent，遵循可复现、隔离、指标驱动、可追踪、可回归等原则：

- 默认运行：`python -m eval_harness`（64 个核心用例，当前 64/64 通过）
- 覆盖范围：任务 UID、角色映射/多视角删除、台词/配音/字幕开关、任务删除、密码强度、白模降级生成等。
- 真实 API 冒烟：`python -m eval_harness --real`
- LLM-as-Judge：`python -m eval_harness --judge`
- 完整模式：`python -m eval_harness --real --judge`（69 个用例）
- 报告输出：`logs/评测报告.md`

## 10. 测试命令

| 命令 | 说明 |
| --- | --- |
| `python -m pytest` | 运行全部后端测试并输出覆盖率 |
| `python -m pytest tests/unit` | 只运行后端单元测试 |
| `python -m pytest tests/integration` | 只运行后端集成测试 |
| `python -m pytest -k "auth or generate"` | 按关键字运行指定测试 |
| `python -m pytest --cov=app --cov-report=html` | 输出 HTML 覆盖率报告 |
| `cd frontend && npm run test` | 运行前端 Vitest 测试（34 个） |
| `cd frontend && npm run build` | 前端类型检查与生产构建 |
| `ruff check .` | 运行 linter |
| `python -m eval_harness` | 运行 Harness 评测并生成报告（默认 64 个） |
| `pytest --alluredir=allure-results` | 运行测试并收集 Allure 结果 |
| `python scripts/generate_allure_report.py` | 生成 Allure HTML 报告 |
